水果连连看 · 运行流程图

这个游戏的运行 = 外层「屏幕切换」+ 内层「一局里点卡片」。两张图分开看就懂。

👉 给小白的一句话：你平时改数据（关卡、金币、图片）就够了，不需要钻进下面这些箭头里。 流程图的用处是：万一游戏「点了没反应 / 不跳关 / 不通关」，你能照图猜出是哪一环出了问题。

图 1 · 五个画面之间怎么跳（外层循环）

启动后游戏进入「主循环」，每秒重画约 60 次；每次画哪一屏，由变量 Main.page 决定。 点不同按钮 = 改 page = 切换画面。实线=前进，虚线=返回。

画面（page） 系统动作 实线=前进　虚线=返回

图 2 · 一局游戏里点卡片发生了什么（内层循环）

玩家每点一次屏幕 → handleTap 先判是不是按钮 → 否则找到卡片 → game.onTapCard 处理。 配对成功才会消除；消到全空才通关。实线=正常推进，虚线=回到「等待点击」继续玩。

画面/结算 游戏逻辑 玩家操作/按钮 判断分支 实线=推进　虚线=回到等待
🔧 排错速查（照图定位）：
· 点了按钮没反应 → 看图1，多半是 ui.js 的 onAction 没匹配到按钮 id。
· 两张一样的图连不起来 → 看图2，是 PathChecker.canConnect 判定路径超过 2 个拐弯。
· 消完不弹结算 → 看图2底部，是 checkWinOrAutoClear / onWin 没触发，或还有残留单张卡。
· 不跳关 → 看图1，是 onWin 里 unlockNextLevel 没写对，或结算面板按钮 id 不对。
