============================================================
第 1 章  这游戏长什么样、怎么玩
============================================================
【玩法】
  屏幕上铺满很多水果卡片（柚子、桃子、西瓜……共 12 种）。
  你用手指点两张「相同」且「能用线连起来」的水果：
    - 连线最多拐 2 个弯（直的 / L 形 / Z 形都可以）；
    - 线不能穿过其他水果，但可以绕到棋盘外圈。
  两张连上就被消除，全部消完就过关。

【过关后】
  - 记录你用的「步数」和「用时」，存为最佳成绩。
  - 奖励金币（第一次过这关 100 金币，重复过 20 金币）。
  - 解锁下一关。
  - 弹出结算面板，可以「下一关 / 重玩 / 分享」。

【总关卡数：20 关】
  - 第 1~16 关：作者手工配好的经典关（难度、布局都写死）。
  - 第 17~20 关：4 个斜向重力演示关「对角坠果·右下/左下/右上/左上」（消除后水果分别沿对角线滑向 右下/左下/右上/左上 角）。
  - 说明：原第 17~576 关（560 个随机关卡）已全部删除，不再自动生成。

【页面（界面）一共有 5 个】
  menu   首页（开始游戏 / 选关 / 商店 / 音效开关）
  levels 选关界面（每页 10 关，可左右翻页，20 关 → 2 页）
  game   游戏界面（棋盘 + 顶部信息条 + 底部 3 个道具按钮）
  win    过关结算面板
  shop   商店（用金币买提示/打乱/炸弹）

第 2 章  文件结构总览
============================================================
项目根目录 = 你打开的这个文件夹「look」。

(1) 入口 & 配置
  game.js            游戏入口文件。它只做一件事：按顺序加载下面 8 个模块。
  project.config.json 微信小游戏工程配置（appid、是否压缩等）。一般不用改。
  game.json          游戏基础配置（竖屏、状态栏等）。一般不用改。
  preview.html       电脑浏览器里预览界面用的（不是手机上用的，开发辅助）。

(2) 核心代码（都在 js/ 文件夹里，按加载顺序）
  js/config.js      ★全局配置：设计尺寸、12 种水果、20 个关卡（16 固定 + 4 斜重力）定义、道具/金币数值。
  js/levels.js      第 1~17 关的「固定棋盘数据」（由 tools/gen_levels.js 生成，别手改）。
  js/storage.js     存档：解锁进度、最佳成绩、金币、道具库存、音效开关（存手机本地）。
  js/pathChecker.js 连连看「连线判定」核心算法（两张水果能不能连上）。
  js/audio.js       音效管理：播放消除/炸弹/胜利等音效，以及背景音乐。
  js/game.js        ★玩法核心：Game 类，管棋盘、点击、消除、重力、冰冻、道具、胜负。
  js/render.js      画面绘制：把棋盘、水果、按钮、特效画到屏幕上（Canvas 2D）。
  js/ui.js          页面/按钮分发：点某个按钮后，决定跳到哪个页面、执行什么动作。
  js/main.js        ★总指挥：屏幕适配、加载图片、接收触摸、主循环、动画(Tween)系统。

(3) 资源
  images/   所有图片：背景(bg_*.jpg)、标题(title_*.png)、3 个道具按钮(btn_*.png)、
            12 种水果(fruit_01~12.png)。
  audio/    所有声音：bgm.mp3（背景音乐）+ 11 个音效(elim/thaw/click/.../hint).mp3。

(4) 工具（tools/ 文件夹，开发者用，不进游戏包）
  gen_levels.js   生成 js/levels.js（固定关卡的随机棋盘）。
  compress_images.py / gen_icon.py / gen_sounds.py  图片压缩、图标生成、音效生成。
  smoke_test.js / test_logic.js / ...  自动测试脚本，验证游戏逻辑没写错。

★ 你最可能改的 3 个文件：config.js（参数）、render.js（画面）、
  ui.js（按钮/页面）。game.js 是核心逻辑，改之前要先理解第 6 章。

第 4 章  必须懂的几个核心概念（很重要！）
============================================================
【4.1 设计坐标 390 × 844】
  游戏内部按一个固定画布大小画图：宽 390、高 844（竖屏手机比例）。
  无论玩家手机多大，代码都按这个尺寸画，再由 main.js 自动缩放到真机屏幕。
  → 你在代码里看到的 x、y 都是「设计坐标」，不是真实像素。

【4.2 网格 / 棋盘（grid）】
  棋盘是 rows 行 × cols 列 的格子。
  但代码里的数组会多套一圈「外框」：行号 0..rows+1、列号 0..cols+1。
    - 1..rows / 1..cols 才是真正放水果的地方；
    - 第 0 行、第 0 列、最后一行、最后一列 是「空的边框」，
      专门给连线绕路用（连连看可以绕到棋盘外面连）。
  grid[r][c] = 水果种类编号（1~12），0 表示空。

【4.3 一张卡片（card）存了什么】
  每个位置除了 grid 上的数字，还有一个 card 对象，记录：
    r, c      它在第几行第几列
    type      水果种类（1~12）
    state     状态：normal(正常)/selected(被选中)/eliminating(正在消失)/
              eliminated(已消失)/mismatch(点错抖动)/hintFlash(提示闪烁)
    visual    视觉：x、y（绘制位置）、scale（缩放，选中会变大）、iceAlpha（冰块透明度）

【4.4 三种「特殊机制」】
  - 重力(gravity)：消除后，水果会往某个方向「塌下来/飘过去」。
      null=不动；down=往下；up=往上；left=往左；right=往右。
  - 冰冻(frozen)：部分水果外面裹着冰，要「点两次」才真正消掉
      （第一次破冰变普通卡，第二次才消失）。
  - 道具(tools)：提示(hint) / 打乱(shuffle) / 炸弹(bomb)，各有免费次数，用完去商店买。

【4.5 主循环 & 动画(Tween)】
  游戏每秒画很多帧（约 60 次/秒），每帧做两件事：
    1) update：推进所有正在进行的动画；
    2) render：根据当前页面(menu/levels/game/win/shop)把画面重画一遍。
  Tween 是一个「补间动画」小工具：让某个数值在一段时间内平滑变化
    （比如卡片从大缩到 0、面板弹入）。改动画快慢就调它的时长参数。

第 5 章  配置文件详解（config.js）
============================================================
打开 js/config.js，从上到下：

【5.1 设计尺寸 & 边距】（第 11~20 行）
  GameGlobal.DESIGN_W = 390;        画布宽
  GameGlobal.DESIGN_H = 844;        画布高
  GameGlobal.TOP_BAR_H = 96;        顶部信息条高度（返回/关卡名/计时）
  GameGlobal.BOTTOM_BAR_H = 116;    底部道具按钮区高度
  GameGlobal.GRID_MARGIN_X = 12;    棋盘左右留白
  GameGlobal.GRID_OVERLAP_RATIO = 0.12;  卡片重叠比例（让卡片看起来更紧凑）

【5.2 12 种水果名字】（第 23~26 行）
  FRUIT_NAMES = ['柚子','桃子','梨子','橘子','紫葡萄','红苹果',
                 '草莓','菠萝','西瓜','青苹果','青葡萄','香蕉'];
  顺序必须和 images/fruit_01~12.png 对应（第 1 个 = fruit_01）。
  想换水果种类，改这里 + 换对应图片（见第 9 章）。

【5.3 第 1~16 关（手工关）】（第 35~132 行，变量 HANDBOOK）
  每一关是一个对象，字段含义：
    id            关卡号（1~16）
    name          关卡名字
    desc          关卡描述（显示在选关/游戏里）
    difficulty    难度星级（1~5，只影响显示星星，不影响算法）
    rows / cols   棋盘行数、列数（行×列必须是偶数，因为要成对）
    fruitTypeCount 用几种水果（1~12）
    gravity       重力：null/'down'/'up'/'left'/'right'
    frozenRatio   冰冻比例：0 / 0.2 / 0.3 / 0.4（0=不冰冻）
    hintEnabled / bombEnabled / shuffleEnabled  这三个道具是否可用（都填 true 即可）
  示例（第 1 关，最简单）：
    { id:1, name:'水果初识', rows:6, cols:4, fruitTypeCount:6,
      gravity:null, frozenRatio:0, ... }

【5.4 第 17~20 关（斜向重力演示关）】
  第 17~20 关是 4 个「对角坠果」演示关，重力分别为 'downRight'/'downLeft'/'upRight'/'upLeft'（水果沿对角线滑向 右下/左下/右上/左上 角）。
  想换方向，改 config.js 里对应关那个 {...} 的 gravity 即可：
    downRight 右下 / downLeft 左下 / upRight 右上 / upLeft 左上。
  原第 17~576 关的自动生成逻辑已删除（config.js 不再有批量生成循环）。

【5.5 选关每页数量】（第 218 行）
  GameGlobal.LEVELS_PER_PAGE = 10;   // 每页 10 关（2列×5行）

【5.6 取关卡配置的函数】（第 221 行 getLevelConfig）
  游戏里要用第 N 关的配置，就调 GameGlobal.getLevelConfig(N)。一般不用动。

【5.7 网格自适应计算】（第 232 行 getGridMetrics）
  根据设计尺寸和关卡行数列数，自动算每张卡片多大、棋盘画在哪。
  一般不用动；想让卡片更大/更小，可微调 GRID_OVERLAP_RATIO（第 20 行）。

【5.8 动画时长（毫秒）】（第 256 行 TIMING）
  ELIM_SCALE 消除缩放时长、ELIM_LINE 连线停留、MISMATCH 点错抖动、
  HINT_LINE 提示线停留、THAW 破冰、GRAVITY_PER_CELL 重力每格、
  BOMB_TOTAL 炸弹、WIN_PANEL_DELAY 胜利面板延迟。
  → 想让某个动画更快/更慢，改这里的数字。

【5.9 经济系统：道具 & 金币】（第 272~285 行）
  TOOLS_DEFAULT = { hint:3, shuffle:2, bomb:1 };  新玩家免费赠送的次数
  SHOP_ITEMS = [ ... ]  商店商品（提示×1、提示×5、打乱×1、炸弹×1，含金币价格）
  COINS_FIRST_CLEAR = 100;   首次通关奖励金币
  COINS_REPEAT_CLEAR = 20;   重复通关奖励金币
  → 想改「送几次道具」「道具卖多少钱」「通关给多少金币」，就改这里。

============================================================
第 6 章  玩法逻辑（js/game.js）
============================================================
Game 是一个「类」，每进一关就 new 一个 Game(levelId)，它管这一局的一切。

【6.1 开局 initLevel()（第 42 行）】
  建好空棋盘 → 决定水果怎么摆（generateLayout）→ 生成卡片（createCards）
  → 如果需要冰冻就冻一部分（applyFrozen）。

【6.2 摆水果 generateLayout()（第 84 行）】
  - 第 1~16 关：直接用 levels.js 里写死的布局，保证每次打开都一样。
  - 其余关：随机洗牌，保证每种水果都成对出现（能消完）。

【6.3 点击一张卡 onTapCard(r, c)（第 215 行）】
  这是玩家点屏幕的核心入口，逻辑是：
    1) 还没选过 → 选中这张（放大、播 select 音）。
    2) 又点到同一张 → 取消选中。
    3) 已经选了一张，再点第二张：
       a. 类型不同 → 点错，抖动一下（showMismatch）。
       b. 类型相同 → 问 pathChecker「这两张能连吗？」
          - 能连 → eliminatePair 消除；
          - 不能连 → 点错抖动。

【6.4 消除 eliminatePair()（第 281 行）】
  处理「冰块」规则（重点！）：
    普+普 → 两张都消失
    普+冰 → 普通那张消失，带冰那张「破冰」变成普通卡（还需再点一次）
    冰+冰 → 两张一起碎掉消失
  消除后画面：画一条金色连线 + 放烟花粒子 + 播消除音。

【6.5 重力 applyGravity()（第 479 行）】
  如果这关 gravity 不是 null，消除后水果会往对应方向塌过去，
  让棋盘重新紧凑。runGravityAnimation()（第 555 行）负责播放这个滑动动画。

【6.6 三个道具】
  useBomb()     第 592 行：随机炸掉一个 3×3 区域（连冰块一起炸），耗 1 次炸弹。
  shuffleCards()第 670 行：把剩余水果的种类重新洗牌（位置不变），耗 1 次打乱。
  showHint()    第 706 行：找出一对能连的水果，画蓝色连线并闪烁，耗 1 次提示。
  每次用道具前都会先检查剩余次数（不够就提示去商店）。

【6.7 胜负判定】
  checkWinOrAutoClear()（第 795 行）：
    - 如果还有可消的牌但「怎么都连不上」了（死局）→ 自动把剩下的全消掉，算赢。
    - 牌全消完 → 触发 onWin()（第 893 行）：播胜利音、解锁下一关、
      记录最佳成绩、发金币、延迟弹出结算面板。

【6.8 小工具方法】
  logicToPixel(r,c)  把「第几行第几列」换算成「屏幕坐标」（画线、画卡都要用）。
  hitTest(x,y)       玩家点屏幕的(x,y)，反查点到了哪张卡（从右下往左上遍历，
                     因为卡片是重叠摆放的，后画的压在上层）。

第 7 章  画面怎么画（js/render.js）
============================================================
渲染层只负责「画」，不负责逻辑。main.js 每帧调用对应页面的渲染函数：

  renderMenu()        第 388 行：画首页（背景 + 标题 + 开始/选关/商店/音效按钮）
  renderLevelSelect() 第 502 行：画选关界面（一页 10 关的格子 + 翻页按钮）
  renderGame()        第 619 行：画游戏界面（顶部信息 + 棋盘 + 底部 3 道具）
  renderWin()         第 711 行：画结算面板（成绩三卡 + 新纪录 + 弹入动画）
  renderShop()        第 564 行：画商店（4 个商品 + 返回）

【画一张卡片 drawCard()（第 171 行）】
  根据 card 的 type 选对应水果图，根据 state 决定要不要画选中光圈、
  抖动、提示闪烁，根据 visual 决定缩放和冰块透明度。

【画连线 drawConnectionLine()（第 236 行）】
  把 pathChecker 算出来的拐点连成折线（金色=消除，蓝色=提示）。

【特效粒子】
  spawnFirework()   消除时的小烟花
  spawnIceShards()  破冰时的碎冰
  spawnBombEffect() 炸弹爆炸
  spawnWinFireworks() 过关满屏烟花
  updateParticles() 每帧推进粒子动画（main.js 的 update 里调用）

★ 改画面最常做的两件事：
  - 改颜色/文字/按钮位置：在对应 renderXxx 函数里调参数（见第 9 章）。
  - 换图片：把 images/ 里的图替换掉，文件名保持一致即可。

第 8 章  按钮和页面切换（js/ui.js + js/main.js）
============================================================
【main.js 总指挥】
  - init()（第 105 行）：拿屏幕尺寸、建画布、加载所有图片、绑定触摸、启动循环。
  - gameLoop()（第 312 行）：无限循环，每帧 update + render。
  - render()（第 330 行）：根据 Main.page 决定画哪个页面。
  - 触摸处理：玩家点屏幕 → bindTouch → 判断点到哪个按钮 / 哪张卡
    → 按钮交给 UI.onAction，卡片交给 game.onTapCard。

【ui.js 按钮分发 onAction(id)（第 79 行）】
  所有按钮都有一个「id 字符串」，点下去后在这里分情况处理。常用 id：
    menu_start    首页「开始游戏」（从最新解锁关开始）
    menu_levels   首页「选关」
    menu_shop     首页「商店」
    menu_sound    首页「音效开关」
    levels_back / levels_prev / levels_next  选关的返回/上一页/下一页
    shop_back     商店返回
    game_back     游戏内返回（回首页或回选关，看从哪进的）
    lv_3          选第 3 关（lv_ 后面是关卡号）
    btn_hint / btn_shuffle / btn_bomb  游戏内三个道具按钮
    win_home / win_replay / win_next / win_share  结算面板按钮
    buy_hint_1 等  商店购买（buy_ 开头）
  想加一个新按钮？在 renderXxx 里画它并 push 一个带 id 的按钮区域，
  再在 onAction 的 switch 里加一个 case 即可（第 9 章有示例）。

第 9 章  常见修改任务（手把手，最重要）
============================================================
下面每一条都给你「改哪个文件 + 怎么改」。

────────────────────────────────────────────────────
任务 1：改第 1 关的难度（行数/列数/水果种类/重力/冰冻）

第 11 章  名词解释 / 排错小贴士
============================================================
【名词】
  连连看    一种消除游戏：连起两张相同且能连通的牌来消除。
  拐点      连线转弯的点；连连看规则最多 2 个拐点（3 段线）。
  重力      消除后剩余牌向某个方向塌落重排。
  冰冻      牌外裹冰，需点两次才真正消除。
  单例/孤卡 某种水果只剩 1 张、无法配对了，游戏会自动帮它消失。
  死局      还有牌但任意两张都连不上，游戏自动清场算赢。
  设计坐标  游戏内部统一的 390×844 画布坐标，与真机屏幕解耦。
  Tween     补间动画工具，让数值在时间内平滑变化。
  Canvas    浏览器/小游戏的 2D 绘图接口，游戏画面全靠它画。
  require   微信小游戏里「加载另一个 js 文件」的写法（见 game.js）。

【排错小贴士】
  1) 改完没效果？确认改的是 .js 文件且在 js/ 目录；微信开发者工具里点
     「编译」(Ctrl+B) 重新加载；浏览器预览就刷新页面。
  2) 游戏白屏/报错？看开发者工具底部「控制台(Console)」的红色报错，
     多半是少了逗号、括号不匹配，或引用了不存在的变量。
  3) rows×cols 必须是偶数，否则水果凑不成对，会卡死或解不开。
  4) 图片换了不显示？确认文件名完全一致（含后缀 .png），且放对 images/ 目录。
  5) 想「全部还原」？这个文件夹有 .git（版本管理），可以用 git 回退；
     改之前最好先备份你要改的那一两个文件。
  6) 不要手改 js/levels.js，它是脚本生成的；改参数请走 config.js 或 gen_levels.js。
  7) 不确定某段代码干嘛？在代码文件顶部几乎都有中文注释，先读注释。

写在最后
============================================================
这个游戏代码写得比较规整，关键位置都有中文注释。
新手改东西的黄金顺序：
  先看 config.js（90% 的数值调整都在这里）→ 再看 render.js（画面）
  → 最后才碰 game.js（玩法逻辑，改错容易崩）。
遇到想实现但不会改的功能，先把「想在屏幕上看到什么变化」写清楚，
再去对应模块里找类似的已有代码照着改，是最稳的办法。
